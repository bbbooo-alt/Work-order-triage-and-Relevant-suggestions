# 一体化控制台使用与解读指南

> 适用对象：`http://127.0.0.1:8770/` 的统一页面（端口 8770）。
> 本文回答三个问题：**怎么用**（操作）、**怎么看**（页面结构与字段）、**怎么理解**（设计口径与结论边界）。
> 文中数字为撰写时落盘报告的示例值；重跑验收后可能变化，一律以页面实时显示为准。

---

## 一、先明白这个页面是什么

它不是第六套验收页，而是把前五步与三项 P0 补缺**串成一条真正会执行的链路**，并提供一个总入口。

| | 五个独立页面（8765~8769） | 一体化控制台（8770） |
|---|---|---|
| 定位 | 每一步的独立验收与交互演示 | 全流程编排 + 统一状态 + 统一操作 |
| 数据 | 各自重跑自己的产物 | **只读**复用各步产物，不覆盖它们的报告 |
| 是否必须同时启动 | 彼此独立 | 不需要。未启动也能用全部功能 |
| 线上写库 | 各自隔离表 | 只写 `pipeline_runs` / `decision_log`，路由为 `dry_run` |

一句话：**独立页面回答「每一步做对了吗」，一体化页面回答「这些步骤连起来能不能跑、跑出来是什么结果」**。

### 启动与关闭

- 双击 `启动项/启动一体化页面.bat`：自动检查本地 PostgreSQL 与 Ollama，自动打开浏览器。
- 地址 `http://127.0.0.1:8770/`；关闭该命令行窗口即停止服务。
- 若 8770 被占用，先关掉旧窗口再启动。

## 二、页面地图

```
┌─ 顶部状态条：PG / Ollama / 当前档位·回退开关 / 八组检查通过数 ─┐
├─ 总控台：一键全量验收 · 跑端到端流水线 · 换一批工单 · 刷新状态
│           ☑ 启用大模型生成   ☑ 使用生成缓存
├─ KPI 八张卡：冻结划分 / 检查数 / 技能预测 / 生成缓存
│              知识片段 / 影子模型 / 流水线审计 / 线上派单
├─ 左栏：工单池（8 张）  →  当前工单（真值 vs 预测对照）
└─ 右栏：五个 Tab
        ① 端到端流水线   ② 验收检查   ③ 标注与抽检
        ④ 上线闭环       ⑤ 报告与产物
```

**顶部状态条**是全局健康度，不是模型效果。`检查 83/83` 表示八组既有检查项全部成立，不代表分类准确率高。

**KPI 中最该盯的是最后一张**：`线上派单` 必须恒为 `0`。任何非 0 都说明演练写脏了线上表。

**左栏工单池**来自冻结 `test` 集的确定性抽样，每张都已有分诊预测与技能预测，保证七段链路能跑到底。点一张即可选中；`换一批工单` 换一组随机种子。左栏「当前工单」里标注了**真值仅用于对照，不参与任何决策**——这是理解全页的关键。

## 三、推荐的第一遍看法（三分钟）

1. 点 **「一键全量验收」**。它做三件事：从各阶段落盘报告只读重算八组检查、真实跑一条端到端链路、比对 11 份报告在验收前后的内容哈希。完成后切到「验收检查」Tab，先看 9 条总检查，再看八组明细。
2. 点 **「跑端到端流水线」**。切回「端到端流水线」Tab，从上往下读七张阶段卡，最后看最上面的**最终处置**横幅。
3. 看不懂某张卡，展开卡底的 **「原始决策数据」**，那里是该阶段未加工的输出。

> 首次生成要调本地 `qwen3:14b`，约 15 秒；命中 `generation_cache` 后几乎瞬时。按钮变灰、出现「正在执行」是正常现象，不要重复点击。

## 四、七段链路逐段怎么读

阶段卡左侧色条与圆点：**绿 = 正常**、**黄 = 设计内的降级/拒答/拒绝**、**红 = 代码异常**。
**黄色不是失败**，恰恰是护栏生效的证据。

### ① 工单接入与 PII 脱敏

看工单号、划分、语种、真值优先级，以及脱敏后的展示文本。脱敏规则：邮箱 → `[EMAIL]`、IP → `[IP]`、含 `+`/空格/连字符的数字串 → `[PHONE]`、纯长数字（如发票号）→ `[NUMBER]`。

理解：真值在这里出现一次，仅用于对照；后面每一段都只用预测值。脱敏是入库前合规要求，不影响检索与生成所用的原文。

### ② 分诊预测

四个格子：`pred_type`（类型）、`pred_queue`（部门）、`pred_priority`（优先级）、`confidence`（置信度）。来自 `triage_results` 的 `triage-l1-v1`，口径是「只在 train 拟合、val 选配置、test 评一次」，置信度是三个任务 `predict_proba` 最大值的平均。低于第二步阈值 `0.45` 会标低置信度。

理解：这是整条链路的起点。`confidence` 后面会被门禁复用，**它不是校准过的概率**，只是相对分数。

### ③ 技能多标签预测（P0-1）

绿色 chips 是 `pred_skills`，另有命中 / 漏报 / 多报的对照。卡片里明确写着「路由阶段使用 `pred_skills`，不使用真值 `required_skills`」。

理解：复盘文档里指出的「二 → 四链路断点」就是这里。第四步原本拿真值技能当输入，属于上界评测；按 13 个技能域各建一个 One-vs-Rest 分类头（样本不足的域会跳过）之后，路由才能拿到线上真正能有的输入。当前 `micro-F1 0.8299`、`子集完全命中率 0.3625`——**多标签很难全对**，所以下游代价要单独量化，而不是假设预测等于真值。

### ④ 混合检索与拒答

看 `hybrid` 策略、关键词权重、最优 KB 相似度、词面重合数、Top5 中权威文档数，以及 5 条片段（排名 / 来源 / 召回通道 / 相似度 / `chunk_id` / 原文预览）。

拒答条件：`词面重合 < 1` 或 `最优 KB 相似度 < 0.30`。触发后卡片变黄，显示「检索拒答：依据不足，后续不生成、不自动生效」。

理解：拒答是**护栏而非缺陷**。词面重合被选为主判据，是因为实测余弦相似度的绝对值区分不了相关/无关查询。混合检索里关键词只给「向量已召回的候选」重排序，避免宽泛 OR 查询把权威文档挤出前 5。

### ⑤ 基于检索片段的生成（P0-2）

左右两栏对照：

- **只检索**（对照组）：返回原文片段数量、是否拒答、前三类来源，未经大模型改写。
- **检索 + 生成**：`steps` 步骤列表、`citations` 引用 chips（`[位置] chunk X · 来源`）、`grounded`、`latency_sec`、`from_cache`、引用有效率。

生成约束是「只能用编号片段、不足就 abstain、不得编造设备型号/版本号/命令/SLA」。越界引用会被剔除并计入有效率。

理解：
- `grounded` 是**词面重合近似**，不是事实核验或 LLM-as-judge，不能当成「无幻觉」的证明。
- 检索拒答时生成直接跳过，返回转人工提示；页面上出现黄色「生成拒答」是正确行为。
- `from_cache=true` 表示同一查询与候选命中 `generation_cache`，此时耗时接近 0。

### ⑥ 技能 ∩ 排班 ∩ 容量路由

看 `status`（`assigned` / `manual_queue`）、选中工程师、合规候选数、技能来源、`rejects` 分布，以及候选表格里的 `score` 与 `parts` 拆解。

硬约束淘汰顺序：未在职 → 技能不匹配 → 排班不覆盖 → 负荷已满。软打分：

```
score = 2.0×熟练度 + 1.2×等级 − 3.0×负荷/容量
        + 0.8×等级(仅 high 优先级) − 1.5(仅值班覆盖)
```

理解：
- `required=[...]` 一行必须来自 `skill_predictions.pred_skills`。若看到它等于真值技能，链路就退回了上界评测。
- 无合规候选人时**降级到人工队列，绝不硬派**；黄色卡片是预期结果。
- 本次是 `dry_run`，只展示决策链，不写 `route_assignments`，更不写线上 `assignments`。

### ⑦ 置信度 + 风险自动档门禁

五项检查逐条打勾：`kill_switch_off`（回退开关关闭）、`confidence_ok`（≥ 准入阈值）、`risk_low`、`retrieval_grounded`（检索未拒答）、`routing_assigned`（有可用工程师）。另有风险等级与理由、`auto_conf_min`、未通过项列表。

风险加分：置信度不足 `+2`、high 优先级 `+2`、Incident `+1`、检索拒答 `+2`、路由降级 `+2`；`0 = low`、`≤2 = medium`、`>2 = high`。

理解：**全局档位 + 单据门禁**是两层。即使单据全部通过，当前档位是 `shadow` 也不会自动生效；反过来，档位是 `auto` 但任一项不过，也必须转人工。

### 最终处置横幅

显示 `门禁放行/拒绝`、`最终处置`（自动生效 / 人工确认 / 转人工处理）、档位、风险、未过门禁、总耗时、审计编号，展开可看链路依赖与隔离说明。

**这是全页的结论位**：一次点击之后，先读这一行，再回头看七段细节。

## 五、其余四个 Tab 怎么用

### ② 验收检查

- **「一键全量验收」** 的 9 项总检查：数据库与 Ollama 就绪、八组检查全通过、P0 产物齐备、七段链路无异常、下游只用预测技能、拒答不硬编、门禁可解释、线上派单 0 行、11 份报告哈希前后一致。
- **八组既有检查**（点组标题展开明细）：评测地基 4、分诊 11、解决建议 15、路由 15、上线闭环 14、P0-1 6、P0-2 9、P0-3 9，共 83 项，全部由落盘报告**只读重算**，不重训。

> 独立页面显示的 `11/11、16/16、20/20、19/19、18/18` 与这里的 `83/83` 不矛盾：前者含页面级重跑、端口隔离与哈希检查，后者是从报告重算的约束项。两套口径各自独立。

### ③ 标注与抽检

- 顶部四格：标注集总数、已人工复核数、生成缓存数、`Recall@5 / MRR`（当前约 `0.9 / 0.6028`）。
- **人工复核标注台**：每行一个工单，下拉选正确 KB 片段，点「复核」写回 `golden_labels` 并置 `reviewed=true`、`annotator=human_via_ui`，同时导出 `eval/golden_set_human.csv`。草稿 ≠ 人工标注，页面把两者分开显示。
- **幻觉抽检评分**：相关性 / 可执行性 / 幻觉程度各 1–5 分，写入 `generation_review` 并导出 `eval/generation_review.csv`。
- **只检索 vs 检索+生成** 对照表：6 组样本（4 个可生成 + 2 个拒答对照），逐行看片段数、拒答、步骤数、引用、grounding、耗时、是否命中缓存。

### ④ 上线闭环

| 控件 | 动作 | 期望结果与解读 |
|---|---|---|
| 影子 / 辅助 / 自动 | 切换全局档位 | 右上角状态条同步；`shadow` 只记录、`assist` 需人确认、`auto` 才可能生效 |
| 打开/关闭回退开关 | 强制退回 `shadow` | 打开后任何自动请求都被拒绝，是上线预案的核心 |
| 高风险 / 低风险探针 | 构造两个合成工单跑门禁 | 高风险应被拒（置信度 0.10、high、Incident、拒答、无工程师）；低风险在开关关闭时应放行 |
| 计算漂移指标 | 只读计算当前窗口 | 阈值：低置信率 0.40、检索拒答率 0.60、路由降级率 0.70、人工改判率 0.35 |
| 执行脱敏 | 对输入文本脱敏 | 检查 `[EMAIL]` / `[IP]` / `[NUMBER]`，纯数字单号不应被误标成电话 |
| 提交人工改判 | 写一条 `feedback_events` | `train` 工单进标注池；冻结 `test` 只观察、`enters_label_pool=false` |
| 消费回流并重训 | 消费 `train` 改判 → 25 倍加权重训 `triage-shadow-v1` → 复用 `evaluate.run()` 对比四个模型 | 输出 9 项闭环检查、`val_delta`、测试集对比；`model_registry` 出现影子版本 |
| 回填 `pred_skills` | 把技能预测重新写回 `triage_results` | 第二步独立页面重跑会清空 `pred_skills`，用它恢复链路输入 |

### ⑤ 报告与产物

- **探测独立验收页面**：列出 8765~8769 在线/未启动与链接。未启动是正常状态，不影响本页。
- **落盘报告**：11 份报告名，点击看内容摘要与原始 JSON（截断显示）。
- **流水线运行历史**：`pipeline_runs` 最近 12 条（工单、档位、门禁、处置、时间）与 `decision_log` 中 `stage='pipeline'` 的审计统计。

## 六、怎么理解：八个必须分清的口径

1. **真值 vs 预测**。左栏真值、卡片里的「命中/漏报/多报」都只用于对照。所有下游决策（技能、优先级、置信度）只用预测值。这是「离线指标」与「线上可用」的分界线。
2. **冻结划分**：`train 22871 / val 2858 / test 2858`。`test` 只评一次；阈值只在 `val` 上选；回流样本只来自 `train`；页面工单全是 `test` 的只读回放，**不代表真实线上流量分布**。
3. **隔离写库**：评测写 `eval_assignments` / `route_assignments`，自动档写 `auto_assignments`，流水线写 `pipeline_runs` + `decision_log`；线上 `assignments` 恒为 0 行。全量验收会校验 11 份报告内容哈希前后一致，防止新功能覆盖旧结论。
4. **三档与回退**：`shadow → assist → auto` 逐档放开，回退开关一开就锁死在 `shadow`。档位是全局的，门禁是单据级的，两层都要过。
5. **自动档门禁的五件事**：开关、置信度、风险、检索依据、路由结果。缺一不可，且拒绝时必须给出理由清单。
6. **拒答与 grounding**：拒答是「没依据就不编」；grounding 是词面重合近似，只能当抽检信号。
7. **影子版与晋升**：重训产出 `triage-shadow-v1`，写 `model_registry`，但 `promoted=false`——本轮只验证流水线，不自动替换线上版本。晋升条件是 val 三任务不掉点且 test 优先级 MAE 不劣化，并需人工确认。
8. **「检查通过」≠「模型效果好」**。`83/83` 说明流程与约束成立；效果要看另一组数字：技能 `micro-F1 0.8299` / 子集完全命中 `0.3625`、路由真值上界 `232` 单 → 预测技能 `229` 单（合规率仍 `1.0`、超时率 `0.12 → 0.134`）、检索 `Recall@5 0.9`。

## 七、当前已知限制（页面上也会如实披露）

- **置信度校准未达标**：`auto_conf_min = 0.85`，该档覆盖仅 `0.38%`、优先级准确率 `0.7273`，未达到「准确率 ≥ 0.90 且覆盖 ≥ 5%」的目标，`qualified=false`。因此自动档在当前数据下**几乎都会保守拒绝并转人工**——这是设计内的安全降级，不是故障。目前只做阈值校准，未做温度缩放 / 保序回归。
- **生成**：本地 `qwen3:14b`，首次调用约 15 秒；提示词约束无法完全杜绝幻觉；标注集初始为规则草稿，人工复核数单独统计。
- **回流重训**：可消费的 `train` 改判样本量很小（当前 3 条，按 25 倍加权），指标变化可能在噪声范围内；本轮验证的是闭环流水线，不是模型收益。
- **数据与合规**：数据集 `cc-by-nc-4.0` 禁止商用；工程师、技能、排班均为造数；三档演练是冻结 `test` 的只读回放，未接真实排班、真实工单与 A/B 分流。
- 文档 `项目现状与计划实施偏差复盘.md` 记录的是当时的快照，P0 三项现已补齐，结论以本页实时数据为准。

## 八、常见场景操作手册

| 想做的事 | 操作 | 看哪里 |
|---|---|---|
| 演示完整链路 | 选工单 → 跑端到端流水线 | 七段卡 + 最终处置横幅 |
| 看「不生成」是什么样 | 取消勾选「启用大模型生成」→ 跑 | ⑤ 生成卡显示拒答对照，⑦ 门禁的 `retrieval_grounded` 变化 |
| 演示自动档放行与拒绝 | 切到「自动」→ 分别点低/高风险探针 | 五项 checks 与 `failed` 列表 |
| 演示一键回退 | 打开回退开关 → 再点低风险探针 | 应被拒绝，理由为「回退开关已打开」 |
| 看不同工单的差异 | 换一批工单 → 逐张跑 | 有的检索拒答、有的能生成、有的路由降级 |
| 演示人工反馈闭环 | 提交人工改判 → 消费回流并重训 | ④ 上线闭环右侧输出 + 模型注册表 |
| 演示标注与抽检 | ③ 标注与抽检 → 复核 / 保存评分 → 刷新标注台 | `reviewed` 状态、`reviews` 数量变化 |
| 排查某项验收失败 | 一键全量验收 → 看失败项 detail | 按报告名去对应独立页面重跑 |

## 九、故障排查

| 现象 | 原因与处理 |
|---|---|
| 页面打不开 | 确认 bat 窗口还在；检查 PostgreSQL `pg_isready -h 127.0.0.1 -p 5432`；确认 Ollama `11434` 可用；确认 8770 未被占用 |
| 生成很慢或超时 | 首次调用本地 14B 模型约 15 秒；勾选「使用生成缓存」；临时取消「启用大模型生成」可做秒级对照 |
| 很多工单检索拒答 | 词面重合 / 相似度未过阈值，属护栏生效；换一批工单看差异 |
| 门禁几乎总是拒绝 | 校准未达标 + 当前默认 `shadow` 档，属预期；用探针演示放行条件 |
| 独立页面显示「未启动」 | 正常，本页不依赖它们；需要时双击 `启动项/启动验收页面_第N步.bat` |

## 十、分步验收台（8771）：想要「逐点测试」时用这个

8770 回答「连起来跑是什么结果」；**8771 回答「每一个点到底在测什么、结果如何」**。它把验收拆成 **140 个可单独点击的测试点**，按项目流程顺序排成 10 组，每个按钮旁直接写明「测什么 / 怎么测 / 期望」，右侧日志控制台逐行给出可追溯的执行过程。

启动：`启动项/启动分步验收台.bat` → `http://127.0.0.1:8771/`。原有的 8765~8769 与 8770 保持不变，也不需要同时启动。

### 页面怎么看

- **流程步骤条**：`0 数据地基 → 1 分诊 → 2 技能预测 → 3 检索 → 4 生成 → 5 路由 → 6 上线闭环 → 7 校准重训 → 8 端到端流水线 → 9 回归/冒烟`，点击定位到对应阶段。
- **左侧测试点卡片**：左边是「运行」按钮，中间三行说明，右边是 `未运行 / PASS / FAIL` 徽章、耗时与最近结论。每个组标题可折叠，也可「运行本组」。
- **右侧日志控制台**：每跑一个点就追加一个日志块，固定五段式：

  ```
  目标   测试点 env.db｜数据库连接与冻结划分
  说明   测什么 / 怎么测 / 期望
  方法   连接 itsm_triage，执行 SELECT split,count(*) ...
  实测   划分 = {'train': 22871, ...}；总行数 = 28587
  判据   三个划分必须恰好为 22871 / 2858 / 2858
  结论   PASS：数据库连接与冻结划分｜判据成立
  ```

  级别用颜色区分；失败时 `结论` 变红并列出未通过的实测值。可「仅看失败」「折叠日志」「导出日志」（纯文本）。

### 按钮分两类

| 类型 | 例子 | 含义 |
|---|---|---|
| 单点 | `env.db`、`triage.r1`、`pipeline.stage_gate` | 只测一个点，日志最详细；`rN` 前缀表示「从该阶段落盘报告重算第 N 条检查项」（只读、不重训），其余为实时执行 |
| 批量 | 快速冒烟 / 回归测试 / 全部顺序执行 / 运行本组 | 逐点串行执行并实时输出日志，顶部显示「正在执行 i/N：测试点名」，可随时「停止批量」 |

回归组包含 5 个独立验收页的真实重跑（8765~8769）、一体化全量验收、报告哈希隔离校验、端口探测，以及 4 类冒烟（环境 / 接口与报告 / 端到端链路 / 全流程首点）。

### 推荐使用顺序

1. 先跑 `0 数据地基` 整组，确认尺子没被动过。
2. 按 `1 → 8` 顺序逐组跑，遇到 FAIL 就看日志里的「实测」与「判据」，不用猜。
3. 最后跑 `9 回归`；这一组会真实重跑各步并**重写各自报告**，所以「报告哈希隔离校验」会现场重新取基线，不会把五步回归的正常重写误判为污染。
4. 改动后第一轮健康检查用「快速冒烟」，完整确认再跑「全部顺序执行」。

### 注意

- `retrieval.suggest`、`generation.live` 会调本地模型，首次可能十几秒；`regress.step2/step3/step5` 是真实重训/重跑，耗时数十秒。页面会逐个显示进度，不是卡死。
- 回归里的第二步重训会清空 `pred_skills`，该测试点执行完会自动回填，日志里会写明回填行数。
- 「端口连通性探测」里独立页面显示未启动是正常状态，不算失败。
- 测试点通过只说明**该点的判据成立**，不等于模型效果好；效果数字仍要看 8770 的一体化页面与落盘报告。
