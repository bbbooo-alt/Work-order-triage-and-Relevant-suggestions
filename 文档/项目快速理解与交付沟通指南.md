## 0. 一页纸：30 秒能讲完的版本

**一句话**：这是一套**本机离线的 ITSM 工单智能分诊原型**——把工单从接入、分诊、技能预测、检索与生成建议、路由到工程师，到自动档门禁与回流重训的整条链路跑通，并且每一步都能复现、能验收。

**三句话（可直接念）**：

> 1. 我们先把「尺子」做好：28,587 条工单一次性冻结成 train/val/test，先跑关键词与轮询两条基线，把进阶门槛写死在配置里，之后所有模型都跟基线比。
> 2. 然后按七段链路逐段实现：TF-IDF + 线性分类头做分诊，13 个 One-vs-Rest 头预测技能，pgvector 混合检索加拒答护栏，`qwen3:14b` 基于检索片段生成建议，规则求解做派单，五项门禁决定是否允许自动档。
> 3. 最后用三层验收兜底：五个独立验收页、一体化全量验收（83/83 检查项 + 9/9 总检查）、以及 140 个可单独点击的测试点；全程用报告哈希和隔离表保证「验收不污染评测」，生产派单表始终为空。

**六个关键词**：`冻结划分` · `基线先行` · `真值/预测分离` · `RAG + 拒答` · `规则可解释路由` · `影子模式 / dry_run`。

**一句话定位（务必主动说）**：**交付的是可复现的离线验证系统，不是可上线系统**。数据集 `cc-by-nc-4.0` 禁止商用，工程师、技能、排班是造数，没有真实流量和业务周期。

## 1. 这个项目在解决什么

### 1.1 业务场景

IT 服务台每天收到大量工单（`subject` 标题 + `body` 正文），需要回答四件事：

| 问题 | 系统里的对应段 |
| --- | --- |
| 这是什么类型 / 该哪个部门 / 多紧急？ | ② 分诊 |
| 处理它需要哪些技能？ | ③ 技能多标签预测 |
| 有没有可参考的历史回复或知识文档？ | ④ 检索 + ⑤ 生成建议 |
| 该派给哪位在岗、有技能、没超容量的工程师？ | ⑥ 路由 |
| 能不能跳过人工直接自动派？ | ⑦ 自动档门禁 |

### 1.2 输入与输出

- **输入**：任意工单文本（8772 用户工作台支持自由输入；离线验收用冻结 `test` 集）。
- **输出**：分诊结论 + 置信度、技能域、命中的依据片段、处理建议步骤、推荐工程师与理由、五项门禁结果、处置结论（当前为「只记录建议，不自动派单」）。
- **谁用**：业务人员用 8772；开发/测试用 8770、8771 和 8765~8769。

### 1.3 明确「不是什么」

不是客服工单系统、不是生产派单系统、不是 SaaS、没有用户体系与权限控制、没有部署配置、不接真实业务数据、不能商用。这句话先说出来，后面所有追问都会好答很多。

| **一体化控制台 8770** | 五步 + 3 项 P0 + 端到端流水线融在一页，一键全量验收 | 解决「分步都过了，连起来到底行不行」 | `pipeline_metrics.json`（9/9 + 83/83） |

## 3. 技术架构：五层 + 一条数据流

### 3.1 分层

| 层 | 选型 | 一句理由 |
| --- | --- | --- |
| 数据层 | PostgreSQL 17 + pgvector 0.8.0；8 张基础表 + 运行时动态表 | 2.8 万行 / 26 MB，单库可全驻内存；关系查询 + 向量 + 事务一体 |
| 模型层 | `TfidfVectorizer(char_wb, 3-5gram)` + `SGDClassifier(log_loss)`；13 个技能 One-vs-Rest 头 | 冷启动不依赖 Ollama、秒级可重跑、好定位掉点 |
| 检索/生成层 | `qwen3-embedding:4b`（2560 → 前缀截断 1024 维，HNSW 余弦）+ GIN 全文 + RRF 融合；`qwen3:14b` 生成 | HNSW 上限 2000 维，故用 Matryoshka 截断；生成只允许用检索片段 |
| 决策层 | 规则路由（技能 ∩ 排班 ∩ 容量 + 加权打分）+ 五项自动档门禁 | 可解释、可审计、可复现；模型不直接决定派单 |
| 评测/展示层 | 11 份 JSON 报告 + 8 个标准库 HTTP 服务（无 Web 框架） | 报告是证据，页面是验收与使用的入口 |

### 3.2 一条工单的旅程（8772 现场演示时用这段）

1. 提交主题与正文 → `lifecycle.redact()` 把邮箱/IP/电话/长数字换成 `[EMAIL]/[IP]/[PHONE]/[NUMBER]`。
2. 内存中的分诊模型（与离线同配置）预测 `type / queue / priority + confidence`，13 个技能头给出技能域。
3. 混合检索召回 top5 片段并判断是否 `abstain`（词面重合 < 1 或最佳 kb 相似度 < 0.30 就拒答）。
4. 若未拒答，`qwen3:14b` 基于编号片段生成 2~4 步建议 + 引用映射，越界引用会被剔除。
5. 规则路由做 `dry_run`：按硬约束过滤工程师、加权打分，返回推荐人和 `reason`，**不写库**。
6. 五项门禁逐项判定，给出是否允许自动档；当前全局模式 `shadow`，处置为「只记录建议」。
7. 结果写入 `user_requests`；人工复核、改判、评分、确认派单写入 `user_feedback` / `user_dispatches`。
8. 生产 `assignments` 依然 0 行，冻结评测数据一行未动。

### 3.3 端口速记

| 端口 | 一句话 |
| --- | --- |
| 8765~8769 | 五个互相独立的单步验收页 |
| 8770 | 连起来跑是什么结果（一键全量验收） |
| 8771 | 每个点到底在测什么（140 个测试点 + 结构化日志） |
| 8772 | 用户真正用的界面 |

## 4. 逐段技术拆解（回答「怎么实现的」）

> 每段的「一句话讲法」可以直接念；「实测」用于被追问时给证据。

### 4.1 ① 评测地基 —— 全项目最该先讲的一段

| 项 | 内容 |
| --- | --- |
| 做了什么 | 28,587 行英/德工单清洗；按 `queue × priority × language` 分组划分，固定 `train/val/test = 22,871 / 2,858 / 2,858`；导出只读 `split_frozen.csv`；跑多数类与关键词两条分类基线、轮询派单基线 |
| 关键技术 | 随机种子 `SEED=20261107`；防泄漏检查 4 项（ID 唯一、标签合法、**同一正文不跨集**、train 比例 ∈ [0.75,0.85]）；门槛预先写死：macro-F1 相对关键词基线 ≥ **+0.03**、无类别 F1 下降、路由合规 ≥ 0.90、超时 ≤ 0.20、`test` 只评一次 |
| 实测 | 多数类基线 `0.1442 / 0.0452 / 0.1913`；关键词基线 `0.307 / 0.2165 / 0.3518`；轮询基线合法派单 46/500、超时 0.212、`load_std 0.47`；冻结校验 28,587/28,587、mismatch 0 |
| 一句话讲法 | 「我们先把尺子固定下来，模型只要不能比关键词基线高 3 个点，就不算过。」 |

### 4.2 ② 分诊

| 项 | 内容 |
| --- | --- |
| 做了什么 | 三个独立线性头分别预测 `type / queue / priority` |
| 关键技术 | `TfidfVectorizer(analyzer="char_wb", ngram_range=(3,5), max_features=30000, min_df=3)`；`SGDClassifier(loss="log_loss", alpha=1e-5, max_iter=20, random_state=42)`；只在 `train` 拟合，`val` 在 `plain / balanced` 两种 `class_weight` 里择优（选了 `balanced`），`test` 只评一次；置信度 = 三任务最大概率的平均，低置信阈值 0.45 |
| 实测 | test macro-F1 **`0.8362 / 0.4280 / 0.5337`**，对关键词基线提升 **+0.5292 / +0.2115 / +0.1819**（全部 ≥ +0.03）；priority MAE `0.7127 → 0.5297`，严重错误率 `0.1043 → 0.0815`；112 条低置信度；英/德分层均不掉点；16/16 检查通过 |
| 一句话讲法 | 「没上大模型，用字符 n-gram + 线性头；冷启动阶段它更快、更好复现，而且确实远超基线。但 `queue` 只有 0.428，标签噪声是已知天花板。」 |

### 4.3 ③ 技能多标签（P0-1，复盘后补的断点）

| 项 | 内容 |
| --- | --- |
| 做了什么 | 13 个技能域各训一个 One-vs-Rest 分类器，把 `pred_skills` 补上 |
| 关键技术 | 与分诊同向量化口径；`class_weight="balanced"`；val 上按 micro-F1 在阈值网格里择优（全局 0.5，各域 0.2~0.7）；样本不足 2 条的域跳过（本轮 `skipped=[]`）；写独立表 `skill_predictions` 并回填 `triage_results.pred_skills`，**不改真值** |
| 实测 | test `micro-F1 0.8299`、`macro-F1 0.7648`、`subset_accuracy 0.3625`；换成预测技能后路由合法派单 **232 → 229**、合规率仍 1.0、超时 `0.12 → 0.134` |
| 一句话讲法 | 「以前路由只能用真值标签，等于上界；补了技能预测后，用预测值重跑，代价只有 -3 单，说明链路真的接上了。」 |

### 4.4 ④ 混合检索与拒答

| 项 | 内容 |
| --- | --- |
| 做了什么 | 从 3,844 条片段（历史回复 3,032 + 工单正文 800 + 权威 KB 12）里召回 top5 |
| 关键技术 | HNSW 向量桶 + GIN 全文桶 + **RRF（倒数排名融合，不是加权和）**，权威 `kb` 单独成桶避免被历史片段淹没；查询抽实词拼 OR 前缀 `to_tsquery`；`abstain` 判据是「查询实词与最佳 KB 文档词面重合 < 1 或相似度 < 0.30」 |
| 为什么拒答这样设计 | 实测相关样本相似度 `0.3814~0.6882`、无关样本 `0.3552~0.6061`，**分布重叠**，余弦绝对值根本分不开，所以改用词面重合 |
| 实测 | `Recall@5 0.9333`、`MRR 0.6706`、`kb_in_top5_rate 1.0`；拒答率向量 0.4667 / 混合 0.2667；**护栏触发，最终关键词权重 0.0** |
| 一句话讲法 | 「混合检索做出来了，但在隔离评测集上没赢过纯向量，系统自动降级回纯向量，绝不拿评测集反向挑参数——这个『不硬凑』比指标好看更值钱。」 |

### 4.5 ⑤ 生成与 grounding（P0-2）

| 项 | 内容 |
| --- | --- |
| 做了什么 | `qwen3:14b` 基于编号片段生成结构化建议 |
| 关键技术 | `/api/chat` 强制 JSON、`temperature 0.1`；prompt 硬约束「只能用给定片段」「证据不足必须 `abstained`」「不许编造型号/版本/命令/SLA/政策」；输出 `steps(2~4) / info_needed / escalation / citations`；越界引用剔除并算 `citation_valid_rate`；`grounding` 用「步骤实词与片段实词交集 ≥ 2」近似 |
| 实测 | 6 条样本：生成 3、拒答 3、平均 grounding `0.5556`、平均延迟 `4.9s`、缓存 3 行；golden set 50 条**弱标注**（`reviewed 0`） |
| 一句话讲法 | 「生成是被片段约束住的，宁可拒答也不硬编；grounding 只是词面近似信号，不是严格的语义蕴含核验，这一点我们如实标注。」 |

### 4.6 ⑥ 路由

| 项 | 内容 |
| --- | --- |
| 做了什么 | 逐条贪心把工单派给最合适的工程师 |
| 关键技术 | 硬约束四关：`active` → 技能交集 → 班次覆盖 → 负荷 < 容量；软打分 `2.0×熟练度 + 1.2×等级 − 3.0×负荷/容量 + 0.8×等级(高优先级) − 1.5(仅值班)`；`SELECT ... FOR UPDATE` 锁工程师行、负荷实时聚合不存静态字段、唯一索引保证幂等；6 线程 /24 单同一时刻并发压测 |
| 实测 | 500 条回放：合法派单 **46 → 232**、覆盖率 0.464、合规率 **1.0**、超时率 `0.212 → 0.120`、`max_load_ratio 0.875`；并发无超派无重复；`load_std 5.1` 劣于轮询 0.47 |
| 一句话讲法 | 「派单不让大模型拍脑袋，用硬约束加可解释打分，理由逐条留痕。负荷均衡确实不如轮询——但轮询是靠乱派换来的均衡，我们优先保证合法和不超容量，并把取舍写进报告。」 |

### 4.7 ⑦ 自动档门禁、三档与回流（第五步 + P0-3）

| 项 | 内容 |
| --- | --- |
| 五项门禁 | `kill_switch_off`（回退开关未打开）、`confidence_ok`（≥ 校准阈值 0.85）、`risk_low`、`retrieval_grounded`（检索未拒答）、`routing_assigned`（派单成功）；全部为真才允许自动档 |
| 三档 | `shadow` 只记录 / `assist` 人确认后生效 / `auto` 仅高置信低风险生效；每档 12 单 × 3 阶段 = 36 条审计日志（三档共 108 条 `decision_log`），自动档沙盒派单 11 条 |
| 校准 | 只在 val 上挑阈值，目标「优先级准确率 ≥ 0.90 且覆盖 ≥ 5%」；**没有达标档 → `qualified=false`**，`auto_conf_min` 取 0.85 |
| 回流重训 | 只消费 `train` 的反馈（3 条，`test` 泄漏 0），复制 25 倍 → 75 行，训出影子版 `triage-shadow-v1`；因 priority MAE `0.5297 → 0.5343` 劣化，**`promoted=false`，不替换线上** |
| 一句话讲法 | 「自动档有五道门，而且校准没达标就明确标 `qualified=false`；回流重训也跑通了，但影子版没赢，所以不晋升——这套系统宁可不动，也不悄悄变差。」 |

### 4.8 8772 在线工作台（与离线验收的区别）

自由文本输入（不依赖冻结工单池）；模型在进程内按相同配置训练一次并缓存；**不写** `triage_results / skill_predictions`，路由固定 `dry_run`，只写 `user_requests / user_feedback / user_dispatches`。一句话：**同一套能力，换了一个不污染评测数据的入口**。

### 5.2 三道防线（讲「质量怎么保证」时用）

1. **冻结划分 + `test` 只评一次**：`train` 拟合、`val` 选配置/阈值、`test` 只用于最终评测；后续演练只读不回流。
2. **真值/预测分离 + 隔离写库**：`tickets` 存真值，预测写 `triage_results / skill_predictions`，回放写 `eval_/route_/auto_assignments`，流水线写 `pipeline_runs / decision_log`，在线写 `user_*`。生产 `assignments` 恒 0 行。
3. **报告哈希前后比对**：11 份报告开跑前取 SHA-256，跑完再比，任何覆盖都会被判失败；回归测试则**现场重新取基线**，避免把「回归自身重写报告」误判为污染。

## 7. 已知局限：讲出来反而加分

### 7.1 三条硬约束（每次交付都要主动声明）

1. **数据集 `cc-by-nc-4.0`，禁止商用**，且出处/下载链接未记录，仓库不分发原始数据。
2. **工程师、技能、排班、12 篇 KB 文档全是造数**，知识库只有英文；所以覆盖率、负荷、漂移阈值都不能当生产预期。
3. **无真实流量、无完整业务周期、无人工抽检、无 A/B**，默认影子模式，生产派单表为空。

### 7.2 仍然存在的结构性缺口

| 缺口 | 说明 |
| --- | --- |
| 评测口径 | `test` 被后续只读演练反复使用，「只评一次」靠约定而非技术强制；近重复跨集未查；超时用硬编码 `SLA_HOURS` 未读 `tickets.sla_due` |
| 标签与置信度 | `queue` macro-F1 仅 0.428，标签噪声未抽检；置信度是三个头概率均值的平均，未做温度缩放校准 |
| 检索与生成 | golden set 是 50 条**弱标注**（`reviewed 0`），有同义反复风险；无语义分块/重叠/cross-encoder 精排；德文工单拒答率偏高；grounding 只是词面近似 |
| 路由 | 覆盖率 0.464（一半转人工），降级只有 `manual_queue` 一种；`load_std 5.1`；无批量最优求解、抢占、跨时区硬约束 |
| 闭环 | 漂移阈值是拍脑袋定值；标注池仅 3 条；`qualified=false`、`promoted=false`；访问控制未做 |
| 工程 | 无 CI / 单测框架、免密 PG、Windows 专属 `.bat`、表结构已偏离最初「8 张表」设计且设计文档未同步 |

### 7.3 「能不能上线」的标准答法

> 现在不能，而且项目自己也没打算上线。它验证的是**方法链路与评测纪律**：门槛预先写死、模型必须赢基线、验收不污染数据、指标不达标就保守降级。要上线还差三件事：换合法且真实的数据源、接真实排班与业务周期做影子观察、把「回流→重训→晋升」从演示变成有校准、有灰度、有回滚的工程流程。

### 7.4 关于复盘文档的时间点

`项目现状与计划实施偏差复盘.md` 写于 2026-11-09，**只依据当时的 5 份报告**，判定 9 处完成判据未达成。其中「技能预测断点」「生成缺失」「回流重训未打通」已由三项 P0 补齐；但「人工标注 golden set」「混合检索确实提升」「三项均优于基线」「真实业务周期」等仍是缺口。谈偏差时务必带上这个时间点，否则会与现状矛盾。

## 8. 高频问答（照着答即可）

**Q1：这个项目全是 AI 写的，你自己理解到什么程度？**
> 坦率说实现由 AI 完成，我掌握的是三件事：**验收口径**（门槛写死在 `eval/thresholds.json`，模型必须赢基线）、**关键取舍**（为什么护栏降级、为什么 `dry_run`、为什么不晋升影子模型）、**能力边界**（哪些没做、为什么不能上线）。细节我不靠记忆，靠证据链：每个点对应 `scripts/` 里的实现、`reports/` 里的数字、8771 里可单独重跑的测试点——需要时现场跑一遍就能核对。

**Q2：怎么证明不是「跑通一次就完事」？**
> 三层验收 + 三道防线：五步独立页、一体化 83/83 与 9/9、140 个逐点测试；冻结划分、真值/预测分离、11 份报告哈希前后比对。回归测试还会真实重跑五个页面并现场取哈希基线。

**Q3：`83/83` 是准确率 83% 吗？**
> 不是，是八组既有检查项共 83 条全部成立。分类效果看 macro-F1：`0.8362 / 0.4280 / 0.5337`，其中 `queue` 明显偏弱，这个短板我们如实写在报告里。

**Q4：为什么用这么「老」的 TF-IDF，不上微调 / 大模型？**
> 本轮目标是先建立可信评测再谈模型递进。字符 n-gram 线性头不依赖 Ollama、可秒级重跑、远超 +0.03 门槛，是最合适的冷启动基线；规划里的 L2（few-shot）/L3（微调）明确留到二期，属于「缩减递延」而非遗漏。

**Q5：RAG 会不会幻觉？**
> 三道约束：只能用编号片段、证据不足必须 `abstained`、禁止编造型号/版本/命令/SLA；引用越界会剔除；另有词面 grounding 近似信号。但它是近似信号，golden set 还是弱标注，所以生成侧人工评分仍是待办。

**Q6：混合检索到底生效了吗？**
> 功能完整（向量 + GIN 全文 + RRF 分桶），但隔离评测子集上出现回退，护栏把关键词权重从 0.3 降为 **0.0**，最终生效的是纯向量。这是刻意不拿评测集反向调参。

**Q7：派单为什么不用大模型？会不会太死板？**
> 派单要可解释、可审计、可复现，还要处理技能/排班/容量硬约束与并发超派，规则求解更合适；模型只负责提供技能与风险信号。逐条贪心是规划里的一期方案，批量最优（匈牙利/最小成本流）明确列为二期。

**Q8：自动档现在开了吗？**
> 没有。全局 `shadow`；五项门禁里 `confidence_ok` 的阈值来自校准，而校准结果是 `qualified=false`（没找到同时满足 90% 准确率与 5% 覆盖的阈值）。所以即便切到 auto，绝大多数工单也会被挡住。

**Q9：数据合规吗？能商用吗？**
> 不能。数据集 `cc-by-nc-4.0` 禁止商用且出处未记录；仓库不分发原始数据。PII 脱敏与审计日志做了，但访问控制没做。商用必须换数据源。

**Q10：为什么 `assignments` 是空的，是不是没做派单？**
> 派单逻辑完整（500 条回放、并发压测、幂等校验都过了），但为了不污染第一步的评测隔离判据，全部写 `route_assignments` / `auto_assignments` 等沙盒表，线上表保持 0 行，路由一律 `dry_run`。

**Q11：为什么有 8 个页面，不能合成一个？**
> 是验收要求演进出来的：先要求五步各自独立页面，后来补 8770 看整体、8771 逐点排查、8772 给业务用。三者面向不同人群，互不依赖。

**Q12：技能预测补上后，效果掉了多少？**
> 用预测技能替代真值标签重跑路由：合法派单 232 → 229（-3），覆盖率 0.464 → 0.458，合规率仍 1.0，超时 0.12 → 0.134。代价很小，说明「真值上界 → 实际可用」这一步接上了。

**Q13：回流重训做了，为什么没上线新模型？**
> 影子版 `triage-shadow-v1` 在 val 三任务基本不掉点，但 test 的 priority MAE 从 0.5297 劣化到 0.5343，按预设规则 `promoted=false`，只在 `model_registry` 登记，不替换线上。

**Q14：指标能迁移到真实业务吗？**
> 不能。工程师/排班/KB 是造数，标签有噪声，golden set 是弱标注，覆盖率 0.464 主要受造数排班影响。这些数字只说明「流程跑通且评测干净」，不是生产预期。

**Q15：如果只让你说一个最有价值的设计，是什么？**
> 「尺子先于模型」+「验收不污染证据」：门槛预先写死、基线先行、冻结划分、报告哈希隔离。在这之上，所有模型结果都可复核、可推翻、可重跑。
