# 第二步 · 分诊（工单分类 ＋ 优先级判定）

> 术语写法：英文原名（中文注解）。
> **前置**：第 1 步已完成——`split`（数据集划分）冻结、`scripts/evaluate.py`（统一评测脚本）可用、基线分数在手。**所有结果必须复用同一把尺子评**。

## 0. 目标

由工单文本预测 `type`（工单类型，4 类）、`queue`（处理部门，10 类）、`priority`（优先级，3 档），结果写 `triage_results`（分诊结果）；`tickets`（工单主表）里的真值（人工标注的标准答案）**一律不动**。

## 1. 输入与输出

- 输入：清洗后的 `subject`（标题）＋ `body`（正文），语种只有 `en`（英文）/`de`（德文），`body_zh`（中文译文）仍为空。
- 输出：`pred_type` / `pred_queue` / `pred_priority`（三个预测值）、`confidence`（置信度）、`pred_skills[]`（预测所需技能）、`model_version`（模型版本），写入 `triage_results`。
- 低置信度不硬判：低于阈值转人工，保留「不确定」出口。

## 2. 技术路线（递进，不要一步到位）

| 层级 | 做法 | 定位 |
|---|---|---|
| L0 | 多数类 ＋ 关键词规则 | 第 1 步已完成的 `baseline`（基线，对照下限） |
| L1 | `embedding`（向量）＋ 线性分类器（`LogisticRegression` 逻辑回归 / 线性 SVM），每个标签一个头 | **冷启动首选**：快、稳、能直接看出增益 |
| L2 | `few-shot`（少样本提示）＋ `LLM`（大语言模型），不训练，靠提示词和相似工单示例 | 作为对照；慢、贵、结果不稳定 |
| L3 | 微调小模型（2.8 万条够用） | 确认 L1/L2 收益后再投入 |

- 建议顺序：L1 → 与 L2 对比 → 视收益决定是否 L3。**不要一上来微调或上大模型**。
- 嵌入模型可复用本地 `qwen3-embedding:4b`（截取前 1,024 维），但它是英德为主；中文场景优先换**多语言嵌入模型**。

## 3. 三个任务要区别对待

- `type` / `queue`：普通多分类，分别训练、分别评 `macro-F1`（宏平均 F1，各类别等权）＋ 混淆矩阵（confusion matrix）。
- `priority`：**有序类别**（low < medium < high），不能只当普通分类。
  - 方案 A：`ordinal regression`（有序回归）或补 `MAE`（平均绝对误差，把 3 档映射为 0/1/2）与相邻错误率。
  - 方案 B（推荐）：`ITIL`（IT 服务管理最佳实践框架）的 `impact`（影响范围）× `urgency`（紧急度）矩阵——先从正文抽这两项，再查表得优先级，可解释且能直接对齐 `SLA`（服务时限）。
- 按 `language` 分层评测：英、德分别报指标，别混着算一个总分掩盖某一语种掉点。

## 4. 语言与数据质量的取舍

- **中文**：优先换多语言嵌入模型，避免翻译带来的信息损失和在线延迟；`body_zh` 只做展示与人工审阅，**不作为训练输入**。
- **标签噪声**：`queue` 与正文存在错配（合成数据）。先人工抽检 200~300 条，再用 `confident learning`（置信学习，如 cleanlab）找可疑标签；**不要为了指标去迎合噪声标签**。
- **类别不均衡**（`Change` 变更约 10%、`low` 约 21%）：类别权重 ＋ `stratification`（分层抽样），以 `macro-F1` 为主指标。

## 5. 格外注意的坑与标准解法

| 坑 | 标准解法 |
|---|---|
| 在 `test`（测试集）上调阈值或提示词 | 冻结清单；调参只用 `train`，选模型用 `val`，`test` 最终只评一次 |
| 只看总分不看逐类 | `per-class F1`（逐类 F1）＋ 混淆矩阵，逐类看召回 |
| 忽略优先级有序性 | 相邻错误率 ＋ `MAE`，或改用 `ITIL` 影响×紧急度矩阵 |
| 英德混合、无中文 | 按 `language` 分层评测；引入多语言嵌入模型 |
| 标签噪声压低模型上限 | 抽样人工校验 ＋ 置信度过滤 ＋ 低置信度转人工 |
| 结果不可复现 | 固定 `seed`（随机种子）、落库写 `model_version`、保留预测快照 |

指标实现有成熟方案：`scikit-learn` 的 `classification_report`（分类报告）直接给 `macro-F1` 与逐类指标。

## 6. 产物与脚本

- `scripts/train_triage.py`：训练 L1 分类头；`scripts/predict_triage.py`：生成预测并写 `triage_results`。
- `reports/triage_metrics.json`：三任务指标（含逐类 `F1`、按语种拆分）。
- 与 `scripts/evaluate.py` 对接，`model_version` 可追溯，一键重跑得到相同数字。

## 7. 完成判据

1. 三个任务的 `macro-F1` 均达到第 1 步写死的门槛（相对基线 ≥ +3 个点），且**无任一类别 `F1` 下降**。
2. `priority` 的相邻错误率 / `MAE` 不劣于基线；英、德分别不掉点。
3. 低置信度出口可用，`triage_results` 与真值完全分离。
4. 结果可一键重跑、可追溯，才进入阶段 3。

> 一句话原则：**先线性、后模型；先可解释、后调参；尺子不变，测试集只看一次。**
