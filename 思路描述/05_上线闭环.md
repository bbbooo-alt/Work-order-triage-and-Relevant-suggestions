# 第五步 · 上线闭环

> 术语写法：英文原名（中文注解）。
> **前置**：阶段 1~4 全部完成——冻结的 `split`（数据集划分）、统一评测脚本、分诊模型、解决建议、路由引擎均已跑通离线评测。

## 0. 目标

让系统接真实工单并持续改进，同时把风险控制在「可观察、可回退」范围内。**离线指标好看不等于上线可用**，本步就是补上这段差距。

## 1. 上线分三档，逐档放开

| 档位 | 做法 | 风险 |
|---|---|---|
| `shadow mode`（影子模式：只记录不生效） | 系统照常输出分诊／建议／派单，但**不改变实际流程**，人工照旧操作，记录两者差异 | 最低，先跑满一个完整周期 |
| 辅助模式 | 建议展示给工程师，由人确认后生效 | 中，人在回路（human-in-the-loop） |
| 自动模式 | 仅对高 `confidence`（置信度）＋ 低风险工单自动生效，其余转人工 | 高，需回退预案 |

**取舍**：先人在回路，别一上来全自动；自动生效的范围要能一键收窄或关闭。

## 2. 回流与标注闭环

- 记录人工的实际分类／优先级／派单与系统建议的差异（`human_override`，人工改判），需要新增反馈表或字段。
- 与 `triage_results`（分诊结果）、`assignments`（派单记录）逐条对比，形成可训练的真实标注。
- 用 `active learning`（主动学习：优先标注模型最不确定的样本）挑选标注对象，把有限人力花在信息量最大的样本上。
- **铁律**：回流数据只进 `train`（训练集）；冻结的 `test`（测试集）永不改动，否则「尺子」会变，历史指标失去可比性。

## 3. 监控与告警

- **数据侧**：`data drift`（数据漂移，输入分布相对训练数据发生变化）、语种占比、低置信度比例。
- **效果侧**：`macro-F1`（宏平均 F1）、超时率、无可用工程师比例、人工改判率、拒答率。
- **工程侧**：检索命中率、派单失败/重试次数、`current_load`（当前负荷）异常。
- 每次模型或规则变更记录 `model_version`（模型版本）、配置、评测分数与生效时间，便于定位掉点。

## 4. 合规与安全

- 数据源许可证 `cc-by-nc-4.0`（禁止商用）：**只够内部验证**，真实生产必须换数据源或取得授权。
- 合成数据 ＋ 造数的工程师/排班：结论只能说明流程跑通，**不能当生产预期**。
- 真实工单含 `PII`（个人身份信息）：脱敏、访问控制、`audit log`（审计日志）留痕。

## 5. 格外注意的坑与标准解法

| 坑 | 标准解法 |
|---|---|
| 离线好、上线掉点 | `shadow mode` ＋ A/B 测试 ＋ 人工抽检，逐档放量 |
| 回流数据污染评测集 | 冻结 `test`，回流只进 `train`；新数据另建时间切分的评测集 |
| 概念漂移（业务规则/工单类型变了） | 分布监控 ＋ 定期校准 ＋ 指标触发重训 |
| 自动化过度、错派难追责 | 置信度阈值 ＋ 人工兜底 ＋ `reason`（派单原因）＋ 一键回退 |
| 重训后无法复现历史结论 | 固定 `seed`（随机种子）、版本化数据与配置、保留预测快照 |
| 合规风险 | 换数据源、脱敏、权限与审计 |

影子模式、A/B 测试、主动学习、漂移监控都是业界成熟做法；`ITIL`（IT 服务管理最佳实践框架）可给事件升级与变更管理流程。

## 6. 产物与脚本

- `scripts/shadow_run.py`：影子模式记录系统建议与人工实际操作的差异。
- 反馈表（人工改判记录）＋ `reports/online_metrics.md`：上线指标与人工抽检结论。
- 监控看板／告警规则、回退开关（关闭自动生效、退回辅助模式）。

## 7. 完成判据

1. 影子模式跑满一个完整业务周期，人工抽检通过，差异原因可归因。
2. 回流标注闭环打通：真实标注能进入下一轮训练，且 `test` 未被污染。
3. 监控与告警生效，回退预案演练过。
4. 合规问题（许可证 / `PII`）有明确处置结论，才允许扩大自动化范围。

> 一句话原则：**先记录、再辅助、后自动；尺子冻结，反馈回流，任何时候都能退回人工。**
